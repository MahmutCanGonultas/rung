01

Terminal

Kullanacağımız araçların çoğunun düğmesi yok — git'in, npm'in, veritabanı bağlantısının. Bu bir eksiklik değil, tercih: tıklamayı kimseye gönderemezsin. Bir komut satırını kopyalayıp yapıştırabilirsin, hatta altı ay sonra kendine bile.

Benzetme

Tarayıcıda F12 → Console'a document.title yazarsın, cevap verir. Terminal aynı şey — ama tek bir sayfayla değil, bütün bilgisayarla konuşuyorsun.

Çalışma klasörü

Terminal her an bir klasörün içinde duruyor. Yazdığın komutlar oraya uygulanıyor. Bir odada durmak gibi: "ışığı aç" dediğinde bulunduğun odanın ışığı açılır. 

pwd/Users/mahmutcangonultas/Desktop/rung

pwd = print working directory

tuzak Terminal yanlış klasörde açılmışsa ve fark etmeden git init yazarsan, Desktop'ın kendisi depo olur. Masaüstündeki her şey takibe girer. Geri almak için gizli .git klasörünü elle silmen gerekir.

Alışkanlık: git komutu yazmadan önce prompt'un sonundaki klasör adına bak.

04

.gitignore

.DS_Store'u sen oluşturmadın — macOS Finder her klasörü açtığında bırakıyor. Depoya koyarsan iki sorun: her açışta değiştiği için gerçek değişikliklerin arasında gürültü yapar, ve ikinci bir kişi katılırsa kimsenin umursamadığı bir dosya için çakışma çıkar.

Takipten çıkarmak: git rm -r --cached node_modules + commit. (--cached olmazsa diskteki klasörü de siler.)

Ama geçmiş yine de dolu kalır. Her git clone o veriyi indirmeye devam eder. Gerçekten silmek geçmişi yeniden yazmayı gerektirir — bütün commit kimlikleri değişir.

Kural: .gitignore koruma, tedavi değil. Bu yüzden .env satırını dosya doğmadan önce yazdık — bir anahtar bir kez commit edilirse yanmıştır, iptal edip yenisini almak gerekir.

bilinen gelenek .gitignore sana "burada bir env dosyası olmalı" der ama içinde ne var demez. Bu boşluk için .env.example geleneği doğmuş: depoya giren, anahtarların isimlerini taşıyan ama değerleri sahte olan bir şablon.
05

git add — sahneleme

Neden tek komut yok? Çünkü bir öğleden sonra iki iş yapmış olabilirsin: bir hata düzelttin ve renkleri değiştirdin. Tek komut olsaydı ikisi aynı kayda girer, birini geri alırken diğeri de giderdi.

kafa karıştıran nokta — burada takıldık git add bir işaret koymuyor. Dosyanın o andaki içeriğinin kopyasını alıp sahneleme alanına koyuyor.

Sonuç: git add yaptıktan sonra dosyayı tekrar düzenlersen, o düzeltme commit'e girmez. Tepsideki fotoğrafta hâlâ eski hâli var. Tekrar git add yazman gerekir.

Böyle bir durumda git status aynı dosyayı iki bölümde birden gösterir: Changes to be committed (eski kopya) ve Changes not staged (yeni düzeltmen).

git add .Bulunduğun klasör ve altındaki her şey. Kaba — önüne ne gelirse alır
git add a.js b.jsHedefli. İki işi iki commit'e bölmenin yolu
06

git commit

Commit atmak kolay, zor olan mesajı yazmak. Altı ay sonra update, fix, son hali, asdasd gibi bir liste sana hiçbir şey söylemez. Ve bir işverenin repona bakınca gördüğü ilk şey bu liste.

altın kural Bir commit bir iş yapar. İlk commit'te esnetilebilir, sonrasında esnetilmez. İki iş varsa hedefli git add ile ikiye böl — sonra birini geri almak isteyince diğeri yerinde kalır.

Geri alma komutu git revert <kimlik> — geçmişi silmez, o commit'in tersini yapan yeni bir commit oluşturur.

07

GitHub'da depo

Bütün geçmişin tek bir diskte duruyor. İki sıkıntı: disk ölürse aylar uçar, ve kimse göremez — kimsenin göremediği portfolyo, portfolyo değil.

git ≠ github Git bilgisayarında çalışan program, internet gerektirmez. GitHub git depolarını barındıran bir şirket — git'in parçası değil, sadece en popüler ev sahibi.
en sık yapılan hata Depo oluştururken "Add a README" / "Add .gitignore" / "Choose a license" kutularını işaretleme.

İşaretlersen GitHub kendi tarafında bir commit oluşturur. O zaman iki ayrı geçmiş olur ve ortak ataları olmaz. Push edince unrelated histories hatası alırsın. Boş bırakırsan bu sorun hiç doğmaz.

github'ın verdiği komut bloğu GitHub sana yedi satırlık bir blok gösterir. O blok boş klasör varsayar. Bizde sadece son iki satır işe yaradı — git remote add ve git push. Körlemesine yapıştırsaydık geçmişe "first commit" diye anlamsız bir kayıt daha girecekti.

Alışkanlık: önüne konan çıktıyı okuyup "bu bana uyar mı" diye sor. Yapay zekâ çıktısı için de aynısı.

git push

git push -u origin main

-u ne yapıyor Açılımı --set-upstream: "yereldeki main, origin'deki main'i takip etsin."

Dal başına bir kez. Bağ kurulduktan sonra git push yeter. Ama yarın yeni bir dal açarsan onun için tekrar -u gerekir — yoksa git "bu dalın upstream'i yok" der.

kimlik doğrulama tuzağı Terminal Password sorarsa GitHub şifreni yazma, çalışmaz. GitHub 2021'de şifreyle girişi kapattı. Oraya bir Personal Access Token gerekiyor.

Nereden: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → yetki olarak repo.

Token bir kere gösterilir. Kaçırırsan yenisini üretmen gerekir. macOS anahtar zincirine kaydeder, bir daha sormaz.

git dağıtıktır GitHub hesabın silinse projen kaybolmaz. GitHub'daki kopya "asıl", seninki "kopya" değil — ikisi de tam. Bütün geçmiş .git klasöründe duruyor.

11

npm init

bilinçli karar Next.js'in create-next-app aracını kullanmadık. Tek komutla otuz dosya gelirdi ve hiçbirini anlamazdın — bir şey bozulunca nereye bakacağını da bilemezdin. Beş adım daha uzun sürüyor, karşılığında her satırın neden orada olduğunu biliyorsun.

npm init sorduğu her soru package.json'da bir satıra karşılık geliyor:

package nameProjenin npm'deki adı
version0.1.0 — henüz yayınlanmamış sürüm
entry pointNode'un baştan çalıştıracağı dosya. Next.js'te işe yaramıyor
typecommonjs bırak — aşağıya bak
licenseMIT — varsayılan ISC gelir, MIT daha yaygın
iki farklı type

repository.type: "git" — hangi sürüm kontrol sistemi. Önemsiz, npm otomatik doldurur.

Üst seviye type — modül sistemi. commonjs (varsayılan, require()) veya module (import). Meşhur Cannot use import statement outside a module hatası buradan çıkar.

Bizde commonjs kaldı: Next.js .tsx dosyalarını kendi derleyicisiyle işliyor, bu alana bakmıyor. module seçersek yapılandırma dosyaları sorun çıkarır.

alışkanlık npm senin yazmadığın alanlar da ekledi — homepage, bugs, directories. Remote adresinden ve klasör yapısından çıkardı. Bir araç senin için dosya ürettiğinde açıp oku.
