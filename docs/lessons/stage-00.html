01

Terminal

Kullanacağımız araçların çoğunun düğmesi yok — git'in, npm'in, veritabanı bağlantısının. Bu bir eksiklik değil, tercih: tıklamayı kimseye gönderemezsin. Bir komut satırını kopyalayıp yapıştırabilirsin, hatta altı ay sonra kendine bile.

Benzetme

Tarayıcıda F12 → Console'a document.title yazarsın, cevap verir. Terminal aynı şey — ama tek bir sayfayla değil, bütün bilgisayarla konuşuyorsun.

Çalışma klasörü

Terminal her an bir klasörün içinde duruyor. Yazdığın komutlar oraya uygulanıyor. Bir odada durmak gibi: "ışığı aç" dediğinde bulunduğun odanın ışığı açılır.

Alışkanlık: git komutu yazmadan önce prompt'un sonundaki klasör adına bak.

07

GitHub'da depo

Bütün geçmişin tek bir diskte duruyor. İki sıkıntı: disk ölürse aylar uçar, ve kimse göremez — kimsenin göremediği portfolyo, portfolyo değil.

git ≠ github Git bilgisayarında çalışan program, internet gerektirmez. GitHub git depolarını barındıran bir şirket — git'in parçası değil, sadece en popüler ev sahibi.
en sık yapılan hata Depo oluştururken "Add a README" / "Add .gitignore" / "Choose a license" kutularını işaretleme.

İşaretlersen GitHub kendi tarafında bir commit oluşturur. O zaman iki ayrı geçmiş olur ve ortak ataları olmaz. Push edince unrelated histories hatası alırsın. Boş bırakırsan bu sorun hiç doğmaz.

github'ın verdiği komut bloğu GitHub sana yedi satırlık bir blok gösterir. O blok boş klasör varsayar. Bizde sadece son iki satır işe yaradı — git remote add ve git push. Körlemesine yapıştırsaydık geçmişe "first commit" diye anlamsız bir kayıt daha girecekti.

Alışkanlık: önüne konan çıktıyı okuyup "bu bana uyar mı" diye sor. Yapay zekâ çıktısı için de aynısı.

npm init

bilinçli karar Next.js'in create-next-app aracını kullanmadık. Tek komutla otuz dosya gelirdi ve hiçbirini anlamazdın — bir şey bozulunca nereye bakacağını da bilemezdin. Beş adım daha uzun sürüyor, karşılığında her satırın neden orada olduğunu biliyorsun.

npm init sorduğu her soru package.json'da bir satıra karşılık geliyor:

package nameProjenin npm'deki adı
version0.1.0 — henüz yayınlanmamış sürüm
entry pointNode'un baştan çalıştıracağı dosya. Next.js'te işe yaramıyor
typecommonjs bırak — aşağıya bak
licenseMIT — varsayılan ISC gelir, MIT daha yaygın
iki farklı type

repository.type: "git" — hangi sürüm kontrol sistemi. Önemsiz, npm otomatik doldurur.

Üst seviye type — modül sistemi. commonjs (varsayılan, require()) veya module (import). Meşhur Cannot use import statement outside a module hatası buradan çıkar.

Burada hata yaptık. commonjs bırakmıştık; gerekçem "Next.js .tsx'i kendi derleyicisiyle işliyor, bu alana bakmıyor" idi. Yanlıştı — Next.js 16'nın paketleyicisi (Turbopack) bu alanı okuyor ve import/export gören dosyada "Specified module format (CommonJs) is not matching..." diye patlıyor.

Doğrusu: type alanını hiç yazmamak. Next.js'in kendi kurulum aracı da yazmıyor. Alan yoksa paketleyici dosya bazında karar veriyor, çakışacak bir beyan olmuyor.

alışkanlık npm senin yazmadığın alanlar da ekledi — homepage, bugs, directories. Remote adresinden ve klasör yapısından çıkardı. Bir araç senin için dosya ürettiğinde açıp oku.

TypeScript

Yeni dil değil

Her geçerli JavaScript, geçerli TypeScript. Üstüne tip işaretleri ekliyorsun.

Yani TypeScript senin koduna ne yapıyorsa, Rung senin İngilizcene onu yapıyor — okur, "burası yanlış" der, metnin kendisine dokunmaz. Denetleyici, çalıştırıcı değil.

Betik nedir

package.json'daki scripts bölümü, projeye özel komut kısayolları. npx next dev de yazabilirdin — ama betik olarak yazınca hatırlaman gerekmiyor, projeye gelen herkes aynı komutu kullanıyor, ve seçenek eklersen tek yerden değişiyor.

devGeliştirme sunucusu. Kaydettiğinde tarayıcı yenileniyor

Komut bitmiyor, terminal sana dönmüyor: sunucu ayakta ve dinliyor. Durdurmak için Ctrl+C.

buradaki keşif — Server Component console.log koyduk ve mesaj tarayıcı konsolunda değil, terminalde çıktı.

Çünkü bu bileşen sunucuda çalışıyor. HTML üretiyor, tarayıcıya sadece o HTML gidiyor; fonksiyonun kendisi tarayıcıya hiç ulaşmıyor.

Sonucu: sunucuda çalışan koda veritabanı şifresi koyabilirsin. İkinci kanıt: sayfa kaynağına bakınca içerik hazır duruyor — klasik React'ta boş bir <div id="root"> görürdün.

.next/ klasörü nedir Klasik React'ta import edip render() çağırarak bağlantıyı sen kurardın. Next.js o kodu kendisi üretip .next/ içine yazıyor.

.next/ = senin elle yazacağın bağlantı kodunun durduğu yer. Adım 13'te "üretilen şey depoya girmez" diye yok saymıştık — üretilen şey tam olarak buymuş.

Adının da bir karşılığı var: kütüphaneyi sen çağırırsın, çerçeve seni çağırır.

19

Katı mod

tsconfig.json'ı da Next.js üretti. Önemli dört satır:

include / excludeHangi dosyalara bakacağı. node_modules hariç
jsx: "react-jsx"JSX'i nasıl anlayacağı
noEmit: trueTypeScript hiç dosya üretmeyecek
strictNext.js false koyuyor — biz true yaptık
kim çeviriyor, kim kontrol ediyor
ÇeviriNext.js (Turbopack) — tip işaretlerini siler. Aptal iş, milisaniye
Kontroltypescript — tipleri inceler. Zeki iş, saniye

Bu yüzden noEmit: true: "dosya üretme, o iş sende değil — sen sadece kontrol et."

Ne zaman hangisi: editörde sürekli kontrol · npm run dev hata engellemez · npm run build durdurur.

katı mod ne yakalıyor

Tipsiz parametre: function f(x) → "x implicitly has an 'any' type"

null kontrolü: el.textContent → "el is possibly null". JavaScript'te en sık çökme sebebi buydu; katı mod onu sen yazarken yakalıyor.

Next.js neden false koyuyor: mevcut bir projeye eklendiğinde yüzlerce hata fırlatabilir. Aracın güvenli varsayılanı — yeni proje için doğru varsayılan değil.

Turbopack — paketleyici Tarayıcı senin .tsx dosyalarını çalıştıramaz, import zincirini de tek tek indiremez. Paketleyici hepsini çevirip birleştiriyor.

Somut olarak: <h1>Rung</h1> yazdığın şey jsx("h1", { children: "Rung" }) hâline geliyor. JSX diye bir şey aslında yok — fonksiyon çağrısının güzel görünen hâli.

20

Neon ve .env.local

Bağlantı dizesi

postgresql://kullanıcı:ŞİFRE@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require

Tek satırda adres + kullanıcı adı + şifre. Region Frankfurt seçildi — veritabanı ile onu sorgulayan sunucu arasındaki mesafe her sorguya gecikme olarak ekleniyor.

bu satır bir şifre Depoya girerse dört şey ters gider: 1 botlar GitHub'ı tarayıp dakikalar içinde bulur · 2 sonraki commit'te silsen de geçmişte kalır · 3 istemci tarafına sürüklenirse her ziyaretçinin F12'sinde görünür · 4 ortam değiştiremezsin.
NEXT_PUBLIC_ kuralı Next.js ortam değişkenlerini varsayılan olarak sadece sunucuda gösteriyor. Adı NEXT_PUBLIC_ ile başlıyorsa derleme sırasında kodun içine metin olarak yapıştırıyor ve tarayıcıya yolluyor.

Yani ön ek, bilinçli bir "yayınla" onayı. Kazara sızdıramazsın, ancak isteyerek sızdırırsın.

neden özel sürücü Klasik sürücü (pg) TCP bağlantısı açıp açık tutuyor — sürekli çalışan sunucuda ideal. Ama Vercel kodu sunucusuz işlev olarak çalıştırıyor: istek gelir, kod kalkar, cevabı verir, kapanır.

@neondatabase/serverless TCP yerine HTTP üzerinden konuşuyor. Kalıcı bağlantı yok, dolayısıyla tükenecek havuz da yok.

Server Component olduğu için async olabiliyor

Sunucu, HTML'i göndermeden önce bekleyebiliyor — bu yüzden bileşenin içinde veritabanı sorgusunu await edebiliyorsun. Tarayıcıda çalışan bir bileşen bekleseydi kullanıcı boş ekrana bakardı.

daraltma — narrowing process.env.X'in tipi her zaman string | undefined, çünkü TypeScript .env.local'in içini bilmiyor. 
const url = process.env.DATABASE_URL;   // string | undefined
if (!url) throw new Error("...");        // boşsa program burada duruyor
const sql = neon(url);                   // string

TypeScript kodun akışını takip ediyor: "boş olsaydı üstte durmuştu, demek ki dolu."

! koyup susturmak da mümkündü — yapmadık. Katı modu açıp susturmak anlamsız. Yan fayda: değişken eksikse anlamsız çökme yerine ".env.local'i kontrol et" yazan hata alıyorsun.

21

Vercel — ilk yayın

localhost = "bu bilgisayar". Laptop kapanınca site yok. Başkasının görmesi için 7/24 açık, adresi ve HTTPS sertifikası olan, Node çalıştırabilen bir makine gerekiyor.

Eskiden: sunucu kirala, Linux kur, nginx ayarla, sertifika al, kod değişince elle güncelle. Vercel bunu devralıyor: GitHub'ı izliyor, her push'ta npm run build çalıştırıyor, sonucu dağıtıyor.

tek cümle git push = yayın. Ve tersi de doğru: git commit yayın değil — commit sadece senin diskinde bir kayıt noktası.
ortam değişkeni ayrıca girilir .env.local .gitignore'da → GitHub'a gitmedi → Vercel görmedi. Bu bir eksiklik değil, tam olarak istediğimiz şey.

Kural: gizli bilgi kodla değil, her ortamla ayrı ayrı taşınır. Senin makinende .env.local, Vercel'de panel. Kod ikisinde de aynı: process.env.DATABASE_URL.

Değeri değiştirmek yetmiyor — redeploy şart, çünkü değer derleme anında koda giriyor.

statik mi dinamik mi — bizi yakalayan yer Next.js varsayılan olarak sayfayı derlemede bir kez üretiyor (○ Static). Yani sorgu bir kere çalışıp sonucu HTML'e gömülüyor — saat donuyor.

Bir de yan etkisi var: sorgu derlemede çalıştığı için DATABASE_URL build anında gerekiyor. Yoksa derleme çöküyor ve Vercel bir öncekini servis etmeye devam ediyor.

Çözüm: export const dynamic = "force-dynamic"; → her istekte baştan çalış.

StatikSorgu derlemede bir kez · tanıtım sayfası, belge için doğru
DinamikSorgu her istekte · kullanıcı verisi için doğru

Rung'ın bütün ekranları dinamik olacak — hepsi senin verini gösteriyor.

nasıl doğrulanır Sayfayı iki kez yenile, saat değişmeli. Ya da yanıt başlıklarına bak: x-vercel-cache: HIT + x-nextjs-prerender: 1 → statik. MISS → dinamik.
özet

Tuzaklar, tek listede

Bu aşamada karşımıza çıkan veya çıkabilecek olanlar. Sonradan düzeltmesi pahalı olanlar üstte.

Gizli anahtarı commit etmek

Bir kez commit edilen anahtar yanmıştır. Sonraki commit'te silsen de geçmişte durmaya devam eder.

Önlem: .env satırını dosya doğmadan .gitignore'a yaz. Olduysa: anahtarı iptal et, yenisini al.

node_modules'ü commit etmek

317 MB geçmişe girer ve her klonlamada indirilir. Sonradan .gitignore'a eklemek takibi durdurmaz.

Olduysa: git rm -r --cached node_modules + commit. Geçmişten silmek için geçmişi yeniden yazmak gerekir.

Yanlış klasörde git init

Masaüstünün kendisi depo olur, oradaki her şey takibe girer.

Önlem: pwd. Olduysa: o klasördeki .git'i sil.

GitHub deposunu README ile açmak

İki ayrı geçmiş oluşur, push unrelated histories hatası verir.

Önlem: depoyu tamamen boş aç.

git add'den sonra dosyayı düzenlemek

Yeni düzeltme commit'e girmez — sahneleme alanında dosyanın eski kopyası duruyor.

Çözüm: tekrar git add. Fark etmek için: git status dosyayı iki bölümde birden gösterir.

Push'ta şifre yazmak

GitHub şifresi çalışmaz, 2021'de kapatıldı.

Çözüm: Personal Access Token üret, repo yetkisi ver, şifre yerine onu yapıştır.

"type": "commonjs" bırakmak

npm init bunu soruyor. Bırakırsan Turbopack import/export gördüğünde "Specified module format (CommonJs) is not matching…" diye patlıyor.

Çözüm: type satırını tamamen sil. Next.js'in kendi kurulum aracı da yazmıyor — alan yoksa paketleyici dosya bazında karar veriyor.

Commit'leyip push etmemek

Vercel GitHub'dan yayınlıyor, senin diskinden değil. Push etmediğin şey canlıya çıkmıyor — ve eski sayfa servis edilmeye devam ettiği için "neden değişmedi" diye şaşırıyorsun.

Teşhis: git status'un ilk satırı. ahead 2 = GitHub senden iki adım geride.

Vercel'e tırnaklı değer yapıştırmak

.env.local'de DATABASE_URL="postgres://…" yazıyor. O tırnaklar dosya biçiminin parçası, Next.js onları soyuyor. Vercel'in paneli bir dosya değil — ne yapıştırdıysan harfi harfine alıyor.

Belirti: password authentication failed. Çözüm: tırnaksız yapıştır, sonra redeploy.

JSX içinde // yazmak

JSX'in içinde // yorum değildir — etiketler arasındaki her şey metin sayılır ve sayfada görünür.

Doğrusu: {/* böyle */}. JavaScript kısmındaki // normal çalışır.

Sayfanın sessizce statik kalması

Veri derlemede bir kez çekilip donuyor. Sayfa çalışıyor gibi görünüyor ama gösterdiği şey eski.

Teşhis: iki kez yenile, değişmiyorsa statik. Ya da npm run build çıktısında ○ (Static) ara. Çözüm: export const dynamic = "force-dynamic".

vim açılır, çıkmayı bilmezsen sıkışırsın.
